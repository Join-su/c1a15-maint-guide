# 아키텍처 그림 작성 가이드 (그림 우선 형식)

이 문서는 `시스템-아키텍처-v2.pdf` 형식의 아키텍처 그림을 다른 세션에서도 같은 품질로 다시 만들기 위한 지시서입니다.
사용자가 "매우 좋다"고 확정한 결과(2026-10-09)를 기준으로 썼습니다.

- 완성본: `docs/architecture/시스템-아키텍처-v2.pdf` · `.png` · `.html`
- 원본 소스: `docs/architecture/source/`
  - `build_architecture.py`: 그림 전체를 만드는 스크립트
  - `render.py`: PNG와 PDF로 내보내는 스크립트
  - `icons/`: Lucide 아이콘 19개
  - `logos/`: Simple Icons 공식 로고 10개
- 처음 받은 단순 구조도: `docs/architecture/시스템-아키텍처.pdf`. 이 그림의 구성 요소와 연결을 하나도 빼지 않고 다시 그린 것이 v2입니다.

## 1. 바로 쓰는 프롬프트

다른 세션에서 새 아키텍처 그림을 만들 때는 아래 블록을 그대로 붙여 넣습니다. `{ }` 부분만 바꿉니다.

```text
{대상 시스템 이름} 아키텍처 그림을 만들어 주세요.
- 구성 요소와 연결의 근거: {기존 구조도 · 문서 경로}
- 형식 기준 문서: /Users/insujo/Documents/repo/c1a15-maint-guide/docs/architecture/아키텍처-그림-작성-가이드.md
- 기준 소스: /Users/insujo/Documents/repo/c1a15-maint-guide/docs/architecture/source/build_architecture.py

반드시 지킬 것
1. 그림 우선: 글을 읽지 않아도 무엇이 어디로 연결되는지 보여야 합니다.
   구성 요소는 실제 모양으로 그립니다(기기, 서버 랙, 원통 DB, 구름 LLM, 공식 로고).
   글은 이름 한두 단어 + 부제 한 줄까지만 씁니다. 설명문과 글머리표 목록은 쓰지 않습니다.
2. 기존 구조도의 구성 요소와 연결은 하나도 빼거나 바꾸지 않습니다. 모양과 배치만 바꿉니다.
3. 화살표: 출발 도형의 테두리에서 검은 점으로 시작하고, 도착 도형의 테두리에서 화살촉으로 끝납니다.
   직각으로 꺾고, 선끼리 교차하지 않으며, 선이 글자를 지나가지 않게 합니다.
4. 글자는 도형 밖으로 넘치지 않게 합니다. 넘침 검사 스크립트로 확인하고, 렌더링한 PNG를 직접 확대해서 봅니다.
5. 결과물은 로컬 파일로 냅니다: 1600x900 SVG를 담은 HTML 1개, 2배 PNG, 1쪽 벡터 PDF.
   claude.ai 링크로 내지 않습니다.
6. 기준 소스(build_architecture.py)의 함수 · 색 · 크기 · 선 규칙을 그대로 재사용합니다.
```

## 2. 사용자가 원하는 것과 거절한 것

| 거절된 형식 | 받은 피드백 | 바꾼 방향 |
|---|---|---|
| 박스마다 설명문과 글머리표를 넣은 카드 나열 | "아직도 절 모르시나요? 저는 글 설명보다 그림으로 바로 인식되는 것을 좋아합니다." | 실제 모양 그림 + 이름만 남김 |
| 아이콘 하나를 붙인 둥근 사각형 | "DB는 원통형 아이콘이나 데이터가 담긴 형상이겠죠?" | DB는 원통, 안에 데이터 줄 |
| DB 안에 무작위 점을 흩뿌린 벡터 표현 | "DB 내 이상한 점들" | 정렬된 데이터 줄 + 작은 벡터 칸 |
| 글자가 칸 테두리에 닿거나 넘침 | "글자가 도형을 넘어가는 형식" | 칸 너비 조정, 긴 글은 12px, 자동 검사 |
| 화살표가 도형 사이 빈 곳에서 시작하거나 끝남 | "화살표 시작점과 끝점이 명확하지 않은 점" | 시작은 테두리 위 검은 점, 끝은 테두리에 닿는 화살촉 |

한 줄 요약: 그림만 보고 3초 안에 "무엇이 무엇에 연결되는지" 읽혀야 합니다.

## 3. 캔버스와 출력

- 캔버스: 1600 × 900 px(16:9). HTML 안에 SVG 하나로 모든 것을 그립니다. HTML 카드 레이아웃은 쓰지 않습니다.
- 글꼴: Noto Sans KR(Google Fonts, 굵기 500/600/700/800).
- 출력
  - `*.html`: 단일 파일, SVG 안에 로고와 아이콘 경로를 직접 넣음(외부 파일 참조 없음)
  - `*.png`: Playwright Chromium, `device_scale_factor=2` → 3200 × 1800
  - `*.pdf`: `page.pdf(width='1600px', height='900px', print_background=True)` → 1쪽 벡터 PDF
- 실행 환경: Python + Playwright(Chromium). 로컬 venv에 `playwright`, `pillow`를 설치합니다.

```bash
cd docs/architecture/source
python build_architecture.py      # architecture.html 생성
python render.py                  # architecture.png · architecture.pdf 생성
```

## 5. 배치: 왼쪽 → 오른쪽 한 방향

요청이 왼쪽에서 오른쪽으로만 흐르도록 열을 나눕니다.

```text
 y 30~110   제목 · 번호 범례(1→5)                          선 종류 범례(실선 · 점선)
 y 180~690  ┌사용자┐  ┌──────────── Docker Compose 영역 ────────────┐  ┌외부┐
            │태블릿│→ │ 웹 서버 랙 │→│ API 서버 [FastAPI | agent] │→│원통 DB│  │구름│
            │모니터│→ │ 알람 발생기│→│                            │→│원통 DB│  │ LLM│
            └──────┘  └─────────────────────────────────────────────┘  └────┘
 y 712~862  └──────────── 운영 밖에서 실행(점선 영역): 카드 3장 ─────────────┘
 y 888      출처 한 줄(오른쪽 정렬)
```

열 x 좌표(기준 소스 값)
- 사용자 62~238
- 웹 서버 · 알람 발생기 378~534
- API 서버 596~1104
  - FastAPI 616~784
  - agent 826~1088
- DB 1188~1384
- 외부 LLM 구름 1462~1600

배치 규칙
- 같은 열의 요소는 세로로 쌓고, 가로 연결선이 같은 높이에서 곧게 나가도록 높이를 맞춥니다.
- 이름은 도형 바로 아래 가운데에 둡니다. DB는 이름을 원통 윗면 안에 넣습니다.
- 운영 밖 요소는 맨 아래 띠에 흰 카드로 넣습니다. 카드는 위쪽 연결 대상 열과 x 위치를 맞춥니다.
- 외부 서비스는 Docker 영역 밖 오른쪽에 둡니다. 이름은 구름 위에 둡니다(구름 아래는 연결선 자리).

## 6. 구성 요소별 그림 규칙

모양이 곧 의미입니다. 같은 종류는 같은 모양으로 그립니다.

| 종류 | 그리는 모양 | 안에 넣는 것 | 글 |
|---|---|---|---|
| 현장 사용자(태블릿) | 짙은 테두리 둥근 기기 + 흰 화면 | 화면 안에 가짜 UI 막대 3개 + 주황 버튼 + React 로고 | 이름 + 기기 한 줄 |
| 사무실 사용자(PC) | 모니터 + 받침대 | 가짜 UI 막대 · 상자 + React 로고 | 이름 + 기기 한 줄 |
| 웹 서버 | 서버 랙(흰 상자 안 슬롯 3개, 초록 LED, 막대) | 랙 아래쪽에 nginx 로고 | 이름 + 역할 한 줄 |
| 외부 입력 생성기 | 흰 상자 | 표 아이콘 → 종 아이콘(주황) | 이름 + "CSV 행 → 알람" |
| API 서버 | 파란 테두리 큰 상자, 왼쪽 위 server 아이콘 + "API 서버" | 안쪽에 두 블록을 좌우로 | 블록 이름만 |
| 웹 프레임워크 블록 | 연한 청록 상자 | 큰 FastAPI 로고 + 이름 + 기능 타일 3개(아이콘 + 단어) | 타일 단어 |
| Agent 블록 | 연한 파랑 상자 | LangGraph 로고 + 노드 5개가 이어진 미니 그래프(사람 승인 노드는 주황 일시정지 원 + "승인 대기") + 기능 타일 6개(2열) | 타일 단어 |
| 관계형 DB | 원통(윗면 흰 타원, 몸통 연초록) | 윗면에 PostgreSQL 로고 + 이름, 몸통에 데이터 줄 4개(아이콘 + 단어) | 줄 단어 |
| 벡터 DB | 원통 | 윗면에 로고 + 이름, 몸통에 데이터 줄 3개 + 줄마다 작은 벡터 칸 5개(초록 농도 6단계) + "원문 + 임베딩 벡터" | 줄 단어 |
| 외부 LLM | 구름 | 보라 sparkles 아이콘 | 구름 위에 이름 + 부제 |
| 묶음(Docker Compose) | 연하늘 둥근 영역 | 왼쪽 위 Docker 고래 로고 + "Docker Compose" | 영역 이름만 |
| 운영 밖 실행 | 회색 점선 둥근 띠 + 흰 카드 3장 | 카드마다 큰 아이콘 + 로고, 또는 쌓인 카드("30"), 문서 묶음 → 작은 원통 | 이름 + 부제 한 줄 |

쓰지 않는 것
- 박스 안 설명 문단과 글머리표 목록
- 흩뿌린 장식 점과 의미 없는 장식 도형
- 목록 항목마다 붙이는 아이콘(타일과 데이터 줄 외에는 아이콘을 붙이지 않음)

## 7. 연결선 규칙

- 종류는 두 가지입니다.
  - 운영 중 호출: 실선 3px, INK
  - 한 번 · 분리 실행: 점선 2.2px(7 6)
- 시작점과 끝점
  - 단방향: 출발 도형 테두리 위 정확한 좌표에서 시작하고, 반지름 4.5 검은 점을 찍습니다. 끝은 도착 도형 테두리 좌표이고, 화살촉(marker refX 8.5)이 테두리에 닿습니다.
  - 양방향(HTTP 왕복, 검색 · 추가 등): 양 끝 모두 화살촉, 시작점은 찍지 않습니다.
  - 좌표는 반드시 도형의 실제 테두리 값으로 정합니다. 도형 사이 빈 곳에서 시작하거나 끝나면 안 됩니다.
- 경로
  - 수평 · 수직 직각 경로만 씁니다.
  - 선끼리 교차하지 않게 경로를 짭니다. 막히면 도형 위치를 옮깁니다.
  - 선이 이름이나 부제 위를 지나가지 않게 합니다. 이름 옆으로 4px 이상 떨어뜨립니다.
- 꼬리표
  - 선 위나 옆에 짧은 단어만 씁니다(HTTP, /api, SQL, import, 검색 · 추가, 빌드, 적재, 임베딩).
  - 13.5px / 800, SUB 색, 흰 외곽선(`paint-order: stroke; stroke-width: 6`)으로 선과 겹쳐도 읽히게 합니다.
- 번호 배지
  - 대표 요청 하나가 지나는 순서를 파란 원(반지름 14, 흰 테두리 3) 1~5로 선 옆에 붙입니다.
  - 제목 아래에 "1 → 5 {요청 설명}" 범례를 둡니다.

기준 소스의 연결 목록(형식 참고)

```python
ar([(238, 266), (378, 266)], 'HTTP', (308, 256), both=True, num='1', npos=(308, 284))   # 태블릿 ↔ 웹 서버
ar([(534, 320), (616, 320)], '/api', (575, 308), both=True, num='2', npos=(575, 340))   # 웹 서버 ↔ FastAPI
ar([(784, 372), (826, 372)], 'import', (805, 400), dot=True, num='3', npos=(805, 346))  # FastAPI → agent
ar([(1088, 330), (1188, 330)], 'SQL', (1138, 318), dot=True, num='4', npos=(1138, 352)) # agent → 운영 DB
ar([(1060, 268), (1060, 152), (1446, 152), (1446, 318), (1462, 318)], 'HTTPS · 문장 생성 · 임베딩', (1250, 142), dot=True, num='5', npos=(1060, 190))
ar([(300, 750), (300, 500), (386, 500), (386, 432)], '빌드', (330, 712), dash=True, dot=True)   # 카드 윗변 → 웹 서버 아랫변
```

## 8. 글 규칙

- 구성 요소마다 이름(1~3단어)과 부제(한 줄, 12~14자 안팎)만 씁니다.
- 고유명사는 영어 그대로 씁니다(React, nginx, FastAPI, LangGraph, PostgreSQL, pgvector, Docker Compose, LLM Adapter).
- 기능은 타일 또는 데이터 줄에 단어로 씁니다(예: 잠금 확인 · 권한 등급 · 근거 검사 · 검색 · LLM Adapter · DB 접근).
- 맨 아래 출처 한 줄에 원칙 한 문장과 기준 문서 · 결정 날짜를 씁니다.
- 말투는 보고서체 명사형입니다. "~요"를 쓰지 않습니다.

## 9. 검증 절차 (매번 실행)

1. **넘침 검사:** SVG 안의 각 글자 bbox가 그 글자를 담은 가장 작은 사각형 안에 있는지 확인합니다. 오른쪽 여백은 3px 이상이어야 합니다. 화살표 꼬리표처럼 상자 밖에 두는 글자는 결과에서 제외하고 봅니다.

```js
// 브라우저에서 실행: 넘친 글자 목록
const R=[...document.querySelectorAll('svg rect')].map(r=>r.getBBox()).filter(r=>r.width<700);
const o=[];document.querySelectorAll('svg text').forEach(t=>{const b=t.getBBox();
 const c=R.filter(r=>b.x>=r.x-1&&b.y>=r.y-1&&b.x<=r.x+r.width&&b.y<=r.y+r.height&&b.y+b.height<=r.y+r.height+8);
 if(!c.length)return;c.sort((a,b)=>a.width*a.height-b.width*b.height);const r=c[0];
 if(b.x+b.width>r.x+r.width-3||b.y+b.height>r.y+r.height)o.push(t.textContent);});o;
```

2. **눈으로 확인:** 2배 PNG 전체를 보고, 연결선이 모인 곳(DB 열, API 서버 오른쪽, 아래 띠)은 잘라서 확대해 봅니다.
   - 선의 시작점이 도형 테두리 위에 있는가
   - 화살촉이 도형 테두리에 닿는가
   - 선끼리 또는 선과 글자가 겹치지 않는가
   - 글자가 칸에 닿지 않는가
3. **누락 확인:** 기존 구조도의 구성 요소와 연결을 하나씩 대조해 빠진 것이 없는지 확인합니다.
4. 원본은 덮어쓰지 않고 `-v2` 같은 새 이름으로 저장합니다.
