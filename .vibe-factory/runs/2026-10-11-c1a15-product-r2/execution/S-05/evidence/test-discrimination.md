# S-05 새 시험의 판별 조건 (점검표 C7)

각 시험이 무엇이 틀리면 실패하는지 적는다. 비교 기준은 시험 안에서 따로 만든 값이다(같은 코드가 만든 값을 그대로 되비추지 않음).

## 화면 component(apps/tech past.test.tsx 15 · apps/lead screens.test.tsx L04 정정 4)

- fixture는 dev 스택 실제 API 응답이다(fixture-capture.py).
- 시험은 화면 요소의 문구 · 잠김 · 호출을 비교한다. 예를 들어 사유가 비면 '정정 저장'이 잠겨 있는지, 409 confirm_required 뒤 확인 창이 뜨는지, confirmed로 다시 보내는지, 메모 창에서 /notes를 부르는지 본다.
- 문구가 API 값과 다르거나 조작 요소가 없으면 실패한다.

## E2E(e2e/tests/s05.spec.ts 6)

- 화면 조작만 쓴다. 정정 · 메모 · 파트장 답 · 반려를 모두 화면에서 한다.
- 매 단계마다 서버 단계 값(`/api/tech/sessions/{id}`)과 화면 문구를 함께 비교한다. 예를 들어 다시 판정 뒤 단계가 ['action', '4.3.2']인지, 보낸 호출 뒤 정정에서 ['call', 'sent']인지, 승인 답 뒤 단계가 restart_check인지 본다.
- AC-44-C3 시험: B 시작 전 체크를 일부만 체크한 상태와 결과 · 메모를 넣은 상태 각각에서 홈 '이어서 하기'와 종 목록 '이어서 하기' 두 경로로 돌아온다. 체크 수 · 체크한 항목 · 고른 결과 · 메모가 다르면 실패한다.
- AC-41-C4: 돌아온 현재 단계에 잠김(.dis)이 남거나, 결과 · 메모를 바꿔도 화면이 바뀌지 않으면 실패한다.
- 외부 요청 0건 · 콘솔 오류 0건(허용 목록 밖)이 아니어도 실패한다.
