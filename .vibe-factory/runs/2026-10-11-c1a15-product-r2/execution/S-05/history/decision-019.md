# 사용자 결정 019 — S-05 G4 전 대조(2026-10-14)

S-05(P-14 정정 API · P-15 지난 화면 · 정정 화면)를 시작하기 전에 S-05 · S-06 계약 전체를 대조했다. S-03 · S-04에서 생긴 동작(반려 뒤 재개 · 결정 018 ③ ④ · 승인 이력 변환)과 정정이 만나는 지점, 그리고 Prototype에 상태가 없는 표시를 사용자에게 물었다(AskUserQuestion, 모두 권장안).

1. **조치 뒤 정정 호출(AC-47-C1)의 '주간 처리' · '직접 확인' 답**: "원인 미상 · 조치는 그대로 (권장)".
   - 보고서 확정 원인은 '원인 미상'으로 한다(S-03 주간 처리와 같은 규칙).
   - 이미 한 조치는 조치 항목에 그대로 남는다.
   - 정정 내용과 답 · 처리 메모는 '미확인 · 요청'에 넣는다.
   - '승인 후 진행'은 결정 012 ②대로 정정 때 하던 단계로 이어서 하고, 보고서는 처음 확정 원인에 정정 표시를 한다.
2. **숙련자 인계를 보내고 답을 기다리는 중의 정정**: "보낸 호출로 보고 상자 붙임 (권장)".
   - 숙련자 인계도 AC-47-C2의 '보낸 호출'로 본다. 다시 판정하지 않고 새 호출도 만들지 않는다.
   - 그 인계에 '보낸 뒤 정비자 정정' 상자를 붙인다(L04 / call_corrected와 같은 모양).
3. **파트장이 이미 답한 호출 뒤, 그보다 앞선 점검 결과를 정정할 때**: "감사 · 보고서에만 남김 (권장)".
   - 다시 판정하지 않고 답도 다시 받지 않는다.
   - 정정은 그 호출 기록에 붙는다. 파트장은 감사 기록(L06 / correction)과 승인 대기 보고서(정정 표시)에서 본다.
4. **정정이 있는 보고서를 승인할 때의 정비 이력(R-번호, 결정 018 ⑤)**: "최신 값 · 무효 기록 빼고 (권장)".
   - 단계 · 결과 · 메모는 정정 뒤 최신 값으로 넣는다.
   - '정정으로 무효'가 된 기록은 뺀다.
   - 정정 사실(정정 n회)만 이력 기록에 남기고, 원래 값은 감사 기록에 둔다.
5. **보고서 초안의 정정 표시(AC-45-C5, Prototype에 정정 든 T09 상태 없음)**: "점검 경로 행에 정정 표기 (권장)".
   - 보고서 '점검 경로' 행 문장에 T08 / corrected_path 점검 경로와 같은 표기를 쓴다. 예: '4.3 이상(정정 1회)', 무효 기록은 '정정으로 무효'.
   - 화면 요소는 더하지 않고 문장 값만 바뀐다(T09 / draft에서 값만 바뀌는 파생 상태로 대조).
6. **잠금 · 조치 · 호출 기록에 덧붙인 메모(T15 / note)**: "지난 화면 · 감사에만 (권장)".
   - 지난 화면의 그 기록 카드(시각 · 메모)와 파트장 감사 기록(L06 / correction의 메모 덧붙이기 행)에만 보인다.
   - 판정 · 보고서 값은 바꾸지 않는다.
7. **S-06에서 미리 정할 두 가지의 시점**: "S-06 G4 전 대조에서 (권장)".
   - ① 시연 10건 완주(AC-16): 정비자 입력 각본 · 파트장 답. 결정 018 ④ 뒤 인계 마감에도 파트장 답이 필요하다.
   - ② 평가 실행기(P-16): 평가 중 호출을 만났을 때의 처리와 지표 계산 정의.
   - 둘 다 S-06 G4를 시작하기 전 대조의 첫 일로 둔다(미룬 일 목록).
8. **조치 뒤 정정 호출의 파트장 쪽 문구(L04, Prototype에 상태 없음 — G4 대조 중 추가)**: "정정 확인 문구로 (권장)".
   - 유형 칩은 '파트장 호출' 그대로 둔다.
   - '필요한 작업'은 '정정 확인 · {절} {점검 이름}({전} → {후})'이다. 예: '정정 확인 · 4.3 흡기 필터 육안 점검(정상 → 이상)'.
   - '승인 후 진행' 설명은 '정비자가 정정 때 하던 단계로 이어서 합니다'(결정 012 ②)다. 주간 처리 · 직접 확인 설명은 그대로이고, 구조는 L04 / call_detail 그대로다.

이 정의는 S-05 slice execution packet의 실행 해석으로 들어간다(plan 변경 없음, 계약 문장 안의 세부 흐름 · 표시). ② · ⑤ · ⑧은 S-05 구조 대조 부록의 파생 상태로 분류한다.

계약 안에서 이미 정해져 있어 묻지 않은 것(packet 실행 해석에 그대로 적는다):
- 정정 호출의 답은 T10 / summary_corrected R-CALLACT 규칙과 결정 012 ② · 018 ③을 따른다.
- 반려로 다시 열린 세션의 정정(AC-48-C3)도 같은 규칙(조치 뒤면 정정 호출)을 따른다.
- 사전 확인 측정값은 기존 precheck_done.values(글)를 정정 대상으로 한다.
- 근거 검사(R8)는 정정 뒤 최신 값을 근거로 본다.

## 추가(2026-10-14, G5 중) — AC-48-C1 화면 범위

9. **확인 질문 답 · B 시작 전 체크 기록의 '메모 덧붙이기'(Prototype 지난 화면에 누를 곳 없음 — G6 전 다시 검토 중 발견)**: "화면은 Prototype대로 · 기록 (권장)".
   - 서버: 두 기록 모두 정정 요청을 거부(not_correctable)하고 메모 덧붙이기는 받는다(진행 · 반려로 다시 열림). 확정 세션(승인 대기 · 승인)은 둘 다 거부한다.
   - 화면: 승인 Prototype 그대로 둔다. B 시작 전 체크는 점검 기록 지난 화면(T15 / check_b) 안의 읽기 전용 패널('그때 모두 확인한 뒤 결과를 보냈습니다')로 보이고 정정 수단이 없다. 확인 질문 답은 지난 화면에 따로 기록으로 나오지 않는다. 두 기록의 '메모 덧붙이기' 화면 버튼은 없다.
   - AC-48-C1의 '정정 없음'은 화면 · 서버 모두 충족, '메모 덧붙이기만'은 이 두 기록에 한해 서버 API까지다. AC-48-C1 문장을 Prototype 화면에 맞추는 일은 다음 plan 판에 적는다(S-04 UF-S04-08과 같은 처리).
   - 앱 코드는 바꾸지 않는다.
