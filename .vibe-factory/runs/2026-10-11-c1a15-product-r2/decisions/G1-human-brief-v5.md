# Gate Brief: G1 / use_case v5

## 쉬운 설명

결정 007 · 008을 Use Case에 넣었다(v3 승인 판에 추가 · 변경).
- 정비자 앱 진행 표시에서 지나온 단계를 누르면 그때 기록을 본다. 서버로 보낸 것은 '제출됨'으로 보기만 되고, 지금 단계에서 고르고 아직 보내지 않은 결과 · 메모만 '수정 가능'이다. 확정 전 보고서는 서버 초안이라 지금처럼 보고서 단계에서 연필로 고친다(SC-26, AC-41).
- 파트장 '승인 후 진행'으로 열린 C등급 점검 뒤에도 같은 규칙으로 이어진다. 이상이면 원인 확정 뒤 조치가 C · D면 다시 호출, 정상이면 남은 후보로 다음 점검이나 호출, 후보가 비면 재가동 확인(SC-27, AC-42).
- 파트장이 등급을 바꾸면 진행 중 세션의 다음 판정부터 적용되고, 이미 열린 화면은 그대로다(SC-28, AC-25-C4).
- 등급은 D를 포함해 모두 바꿀 수 있고, 올리든 낮추든 모든 변경에 경고를 확인해야 저장된다(SC-38, AC-25-C3).
- B등급 점검 · 조치는 시작 전 체크리스트를 모두 확인해야 결과 입력 · 진행 버튼이 열린다. 절에 목록이 없으면 공통 시작 전 확인 목록을 쓴다(SC-04 · 05 · 28, AC-43).

규모: scenario 42개, 수용 기준 43개, 논리 흐름 14개. v3에서 바뀐 수용 기준은 AC-25뿐이다(C3 대체, C4 추가). Critic: v4 revise(보고서 초안 위치 · B 조치 조건 누락) → v5 pass.
