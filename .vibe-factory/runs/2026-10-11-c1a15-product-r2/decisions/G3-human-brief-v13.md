# Gate Brief: G3 / prototype v13

## 쉬운 설명

v9를 써 보고 주신 Design Feedback 4건을 고쳐, 승인된 화면 58개(새 화면 T15 지난 단계 보기 5개 · T06 / b_precheck · L05 / raise_warning 포함)와 파생 상태 4개를 한 문서(`prototype/v13/index.html`)에 담았다. 검토 이력: v10은 독립 검토(G3-10)에서 고칠 것 3건(진단 화면 '다음 점검'이 옛 등급, 확정 보고서 값이 홈 · 파트장 검토로 안 이어짐, T15 진단 창 구조 증거 없음)이 나와 v11로 고쳤고, v11 확인 검토(G3-11)에서 1건(반려 뒤 정비자가 고쳐 다시 확정한 내용이 기본 경로에서는 파트장 검토에 안 보임)이 남아, 결정 009('v12 새 회차')로 v12에서 고쳤다. v12 검토(G3-12)에서 1건(승인한 C 점검이 나중에 B로 바뀌면 시작 전 체크리스트 없이 결과 입력이 열림)이 나와 v13에서 고쳤다(B는 승인 기록과 관계없이 체크리스트가 먼저).

## 상태·규칙·위험 그림

- **자동 자체 시험:** 수용 기준 20개 · 미룬 기준의 화면 조건 6개 AC · 조작 시험 CTL 17개, 모두 통과(`verification/g3-v13/selftest-result.json`).
- **조작 요소 전수 점검(넘기기 전 조건):** 148개 시나리오 × 3650개 요소를 하나씩 실제로 눌러 결과를 대조했다. 이름표와 다른 결과 0 · 연결 없음 0 · 오류 0. 결함 복사본 7개에서는 점검이 결함을 잡았다(`verification/g3-v13/control-audit.json`).
- **음성 시험:** 결함을 하나씩만 넣은 복사본 40개(이번 피드백 결함 10개와 G3-10 · G3-11 · G3-12 지적 4개, 승인 뒤 D 1개 포함) 모두에서 그 결함을 맡은 시험이 실패했다(`verification/g3-v13/mutation-check.json`).
- **구조 보존:** Region 199개가 모두 있다. 승인 화면과 마크업 hash가 58개 중 53개 같다(다른 5개는 v9와 같은 로그인 입력칸 4개 · T09 / check_failed 실패 문구). 지난 단계 보기 창 5종은 승인 T15와 골격 · 단계 목록 글자까지 같고, 새 경로 27개 화면에서 화면 틀 넘침 0건.
- **Critic 이력:** 회차 1~6(v1~v9, 마지막 v9 pass · 승인). 회차 7: v10 revise → v11 revise(확인), 규칙대로 멈춤 → 사용자 결정 009(DEV-10). 회차 8: v12 revise(`critics/G3-12-review.json`) → v13 pass(`critics/G3-13-review.json`).
- **prototype 한계:** 버튼 없이 메모만 보내는 확인 질문은 첫 지시에서만 뜬다(v9와 같음). 자체 시작 전 체크리스트가 있는 B 점검(2.5 · 5.5)은 이 sample 흐름에 나오지 않는다. 첫 판정이 호출인 진단 화면은 승인 화면에 없어 안내만 띄운다. 확인 불가 뒤 다음 점검이 B면 '확인 불가 1회' 배너 대신 시작 전 체크리스트가 먼저 보인다.
